# ChessForge 長期訓練設計（2026-11-17）

## 現有系統檢查
React 18 + TypeScript + chess.js + react-chessboard；FastAPI/python-chess/SQLAlchemy/SQLite；本機 Stockfish 19 與 Pages 的 Stockfish 17.1 Lite Worker。已有公開同步、合法 PGN、逐步分析、MultiPV、錯步證據、弱點分類、批次分析、PV 與響應式介面。248 盤原始資料全數驗證，現在持續同步；沒有訓練作答、記憶排程、掌握度或每日課程資料。

保留兩個執行模式。GitHub Pages 無法運行 Python，訓練規則統一寫成可測試的純 TypeScript；SQLite 與 IndexedDB 提供相同 revision/CAS 持久化介面。避免兩套排程演算法互相漂移。新增 training_state 表保存版本化文件（cards 排程、attempts、daily plans、settings）；用樂觀鎖拒絕多分頁／LAN 同時覆寫。這是單人本機資料，不是多租戶伺服器或防作弊系統。

## 決策與優先序
1. 真實棋局產生卡片：只用已完成分析、自己的走法。失誤卡 + 前 8 回合的開局決策卡。同一局面合併、保留出處與頻率；不憑少量樣本推算 Elo。
2. 每日安排 5/10/15 題：到期優先、弱點與遭遇頻率排序、新題每日有上限、每盤最多兩題；保存當天清單，重新開啟可續練，答完不再灌新題。
3. 先走棋再揭答案：棋盤點選或拖曳，也支援 SAN/UCI；可回看之前的真實走法；提示、看答案、錯答均記錄，不能靠重試刷掌握度。
4. 替代走法：MultiPV 內與最佳差距 ≤30cp 可接受。其餘合法走法只對已匯入的完成對局局面進行新引擎比較，統一白方評估再轉走棋方。將死不當作普通兵分。引擎失敗不計錯。
5. 間隔複習：獨立正確後 1/3/7/14/30/60 天；錯或提示隔天重看。三個不同日期的無提示正確、跨至少七天才標示「延後回憶穩定」，不是宣告棋力已掌握。當天重練不升級，提前練習不升級。答案集合改變後重設排程、保存歷史。
6. 開局工作台：按自己的白／黑棋與實際前四半步分組，顯示樣本量、戰績、頻率、可訓練局面與已知候選；不購買或複製課程。不把短序列誤稱標準 ECO 開局。
7. 成長：分項首次無提示作答、到期回憶、近期／先前相同來源時間控制的每百步失誤率，與訓練後同局面再犯紀錄。顯示分母及樣本不足，不把觀察性變化說成訓練因果。
8. 保存與可攜：版本化訓練備份匯出／還原；資料庫與瀏覽器皆保存。Pages 不依賴付費伺服器，原生 LAN 用既有存取碼。不同裝置仍需各自同步棋局、手動搬移訓練備份，未建立雲端帳戶。

## 邊界與後續
本次把持續練習、排程與追蹤做成正式功能，不做展示資料。仍不承諾從 547 到特定 Elo 的成效，也不能以短期自動測試證明長期教學效果。基礎規則課程、完整殘局對弈教練、外部戰術題庫、全開局百科、對手模擬、FSRS 參數擬合、端對端加密跨裝置同步、完整離線 PWA 尚未實作。下一階段優先用數週實際紀錄驗證排程與錯誤率，再擴充有證據的戰術解說與殘局課程。
